## Mission

Fix two remaining categories of foundation codegen issues.

### Issue D1: Missing dependency use/take/release methods in implementation main modules

Implementation main modules (e.g., `vscf_curve25519.h/.c`) should include `use_X()`, `take_X()`, and `release_X()` methods for each dependency. CG-029 added these for class modules but the implementation main module renderer (`render_implementation_c_module()`) doesn't call the dependency method rendering.

Example: `vscf_curve25519` should have `use_random`, `take_random`, `release_random`, `use_ecies`, `take_ecies`, `release_ecies` — but they're missing.

Fix: call the dependency method rendering (from CG-029's `_render_dependency_methods()` or equivalent) in `render_implementation_c_module()`.

### Issue F1: Missing library-specific assert macros in module output

The `vscf_assert` module should include library-specific assert macros like `VSCF_ASSERT_LIBRARY_MBEDTLS_UNHANDLED_ERROR` and `VSCF_ASSERT_LIBRARY_MBEDTLS_SUCCESS`. These are generated by the GSL pipeline based on `<require library="mbedtls">` declarations in the project.

The legacy output includes these macros in the assert module. The new codegen doesn't generate them.

Fix: detect library requirements across the project and generate corresponding assert macros in the assert module renderer.
