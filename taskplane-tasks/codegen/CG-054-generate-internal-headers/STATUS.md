## Notes

**Step 0 findings:**
- Legacy `_internal.h` pattern: license → warning → description → header guard → includes (`_library.h`, impl header, extra type headers) → `extern "C"` → generated section (init_ctx, cleanup_ctx, init_ctx_with_X) → footer
- No vtable registration or did_setup/did_release in legacy `_internal.h` — those live in `_internal.c`
- Current `render_implementation_internal_c_module` already produces correct XML structure that generates both `.h` and `.c` content
- Key fix needed: constructor `init_ctx_with_X` stubs use `visibility="private"` but should match legacy `VSCF_PUBLIC` → actually legacy constructors visible publicly while init_ctx/cleanup_ctx are private. Must check if VSCF_PRIVATE is actually correct for the build.
